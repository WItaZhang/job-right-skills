# job-right-skills：先弄清想要的工作，再准备申请

这是一个计划在 Claude Code 中使用的求职助手插件。它先通过对话帮你说明白想要什么样的工作，再带着这些要求查找岗位、解释是否合适，最后把你选中的岗位申请准备到人工检查和提交之前。

当前状态：截至 2026-09-23，三个流程都已实现；访谈与找岗位各有一次真实运行记录，填表的浏览器部分待用户本机验证（见 chrome-precheck.md）。本文描述预期的使用体验；实现细节见 [implementation-plan.md](./implementation-plan.md)，待解决的问题见 [implementation-plan-review.md](./implementation-plan-review.md)。

## 你会怎样使用它

### 第一步：聊清楚你真正想要的工作

你可以从一句很模糊的话开始，例如：“我想去美国做 AI 相关工作。”

助手会接着问：为什么想去美国？是工作内容、科技社区、家庭安排，还是其他原因？如果别的地方也能满足你关心的条件，你是否接受？哪些条件可以妥协，哪些不满足就不会考虑？

这些回答会整理成一份“求职方向卡”。你可以随时说不知道、跳过或暂停，不需要为了完成问卷编一个答案。你改主意时，卡片会记录改了什么、为什么改，保留此前的版本依据。

如果你确认两条路线都能接受，例如“留在当前城市找稳定工作”和“搬去另一座城市寻找更大的成长机会”，可以分别保存两张卡。助手不能擅自把你要求同时满足的条件拆开。

### 第二步：带着方向卡找岗位，并说明依据

助手会发现可能相关的公司，确认其官方招聘入口，再读取岗位资料。第一版覆盖使用 Greenhouse、Ashby、Lever 招聘系统的公司，搜索引擎用于发现公司线索。

每个岗位都会说明：哪些底线符合，哪些明确不符合，哪些信息还没查到；也会列出软偏好的满足情况和取舍。理由附上来源和检查时间。

例如，你确认“必须能在目前居住的地区远程工作”：岗位明确要求每周到办公室，就应显示冲突；岗位只写 remote 却没说明允许的地区，就应显示待核实。网页打不开不能当成职位已经关闭。

你自己选择感兴趣的岗位，助手不会因为一个岗位看起来合适就自动决定申请。

### 第三步：准备你选中的申请

助手会使用你提供并确认的履历资料，打开申请表、填写有依据的信息、上传你指定的简历。需要自由作答的问题会生成草稿，并在审阅清单中标出。

结束时，你会看到表单和一份检查记录：填了什么、依据是什么、哪些内容还需要你检查或补充。你负责最后的审阅、同意项和提交。登录、验证码等需要你处理的步骤会暂停交接。

第一版目标是停在最终申请提交之前。文件上传和网站自动保存可能提前把资料发送给招聘网站，这与最终提交是不同动作。

## “重点”和“底线”有什么区别

**底线**是你确认不能退让的条件，每一条都应检查。

**重点**是最能说明这个求职方向的少数几条底线，用于组织搜索和介绍方向。方案里把它们称为 `key_fields`。

比如“做技术岗位”和“希望在科技社区活跃的城市工作”是方向重点，你还可能有薪酬底线、搬迁时间和工作授权要求。这些条件即使没被选作方向重点，也不能在筛选时忽略。

方案规定确认的方向需要 2–4 个重点。如果你只有一个底线，系统应如实保存草稿并支持探索，不能为了满足数量要求替你增加条件。这项产品规则仍需在实际访谈中检验体验。

## 最终会留下什么

| 产出 | 对你的作用 |
|---|---|
| 求职方向卡 | 记住你要什么、为什么，以及什么不能妥协 |
| 岗位候选清单 | 把合适、不合适、还需核实的原因摆出来 |
| 个人事实档案 | 保存经你确认的经历、联系方式等，减少重复输入 |
| 申请检查记录 | 让你检查表单内容、依据、自由题草稿和剩余事项 |

私人运行资料计划保存在你选择的工作目录，并从 Git 提交中排除；公开仓库只放代码、说明和合成示例。忽略规则只解决误提交问题，不能理解为资料不会被模型或招聘网站处理。

## 第一版做到哪里

交付形式是一个插件里的三个工作流程：访谈、找岗位、准备申请。它首先服务于愿意在 Claude Code 对话中使用工具的人，暂不包含独立的求职网站界面。

第一版验证的重点是：能否忠实理解用户、能否给出有证据的筛选理由、能否把选中的申请准备好并交回人。LinkedIn、Boss 直聘等额外来源不在本轮自动采集范围内，也不承诺找到全部岗位、绕过网站风控或提高到某个录用概率。

建议的首次完整演示是：一段合成访谈形成方向卡，找到一个有来源的岗位，由人选中，再在受控测试表单里准备申请并停下。先证明这条流程可靠，再增加覆盖。
